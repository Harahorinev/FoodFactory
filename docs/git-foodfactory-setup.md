# Локальный Git-репозиторий FoodFactory на macOS

Эта инструкция рассчитана на учебную 1С:Предприятие 8.3.27.1688 и файловую информационную базу `FoodFactory` на Mac с Apple Silicon. Git будет хранить **текстовые исходники**, а не саму информационную базу.

## 1. Что хранить отдельно

Не помещайте рабочую информационную базу внутрь Git-репозитория. Удобное разделение:

```text
~/1C_Bases/FoodFactory/             # файловая база 1С, вне Git
~/projects/FoodFactory/             # репозиторий с исходниками и учебными материалами
```

Файл базы `1Cv8.1CD`, выгрузки информационной базы `*.dt`, бинарные файлы конфигураций и обработок, временные файлы и секреты коммитить нельзя. Git не заменяет резервное копирование базы.

## 2. Подготовить Git

Откройте Terminal и проверьте Git:

```bash
git --version
```

Если macOS сообщает, что инструменты разработчика не установлены:

```bash
xcode-select --install
```

Завершите установку в системном окне, затем снова выполните `git --version`.

## 3. Создать структуру репозитория

```bash
mkdir -p "$HOME/projects/FoodFactory/src/configuration"
mkdir -p "$HOME/projects/FoodFactory/src/external-processing"
mkdir -p "$HOME/projects/FoodFactory/docs"
cd "$HOME/projects/FoodFactory"
```

Рекомендуемая структура:

```text
FoodFactory/
├── .gitignore
├── AGENTS.md
├── PROGRESS.md
├── docs/
│   └── 28-day-intensive-plan.md
└── src/
    ├── configuration/              # XML-выгрузка основной конфигурации
    └── external-processing/
        └── <ИмяОбработки>/         # каталог создаёт экспортёр 1С
```

- `src/configuration/` — исходники метаданных и модулей конфигурации.
- `src/external-processing/` — общий каталог назначения; экспортёр 1С сам создаёт внутри каталог каждой внешней обработки.
- `AGENTS.md` — правила учебной работы.
- `PROGRESS.md` — только фактически подтверждённый прогресс.
- `docs/28-day-intensive-plan.md` — учебный план; он не означает, что будущие задания уже выполнены.

Git не хранит пустые каталоги. Это нормально: `src/external-processing/` появится в истории после первой выгрузки обработки.

## 4. Скопировать учебные документы

Исходные `AGENTS.md`, `PROGRESS.md` и `docs/28-day-intensive-plan.md` находятся в **Project Context Cursor**, а не в файловой системе вашего Mac. Путь вида `/cursor/stores/...` нельзя подставлять в локальную команду `cp`.

Откройте или скачайте каждый файл из Project Context и сохраните его содержимое локально без переименования:

```text
Project Context/AGENTS.md
    → ~/projects/FoodFactory/AGENTS.md

Project Context/PROGRESS.md
    → ~/projects/FoodFactory/PROGRESS.md

Project Context/docs/28-day-intensive-plan.md
    → ~/projects/FoodFactory/docs/28-day-intensive-plan.md
```

Проверьте наличие и непустое содержимое:

```bash
cd "$HOME/projects/FoodFactory"
test -s AGENTS.md
test -s PROGRESS.md
test -s docs/28-day-intensive-plan.md
printf 'Учебные документы сохранены локально.\n'
```

Если одна из трёх проверок не пройдёт, команда остановится до сообщения `Учебные документы сохранены локально.`. Не создавайте пустые заглушки вместо документов.

## 5. Выгрузить исходники конфигурации через Конфигуратор

Не используйте непроверенные параметры командной строки 1С. Выполните выгрузку интерфейсом Конфигуратора:

1. Сделайте обычную резервную копию базы вне репозитория.
2. Откройте информационную базу `FoodFactory` в режиме **Конфигуратор**.
3. Сохраните основную конфигурацию.
4. Выберите **Конфигурация → Выгрузить конфигурацию в файлы…**.
5. Укажите каталог:

   ```text
   /Users/<ваш-пользователь>/projects/FoodFactory/src/configuration
   ```

6. Дождитесь завершения и убедитесь в Finder или Terminal, что каталог содержит выгруженные XML-файлы и тексты модулей:

   ```bash
   find "$HOME/projects/FoodFactory/src/configuration" -type f -print
   ```

На последующих шагах обучения выгружайте конфигурацию повторно в тот же каталог после сохранения изменений. Обновление конфигурации базы данных нужно для запуска и проверки изменений в 1С, но в Git попадает именно файловая выгрузка основной конфигурации.

Не путайте команды:

- **Выгрузить конфигурацию в файлы…** — нужные текстовые исходники;
- **Сохранить конфигурацию в файл…** — бинарный `*.cf`, не нужен в Git;
- **Выгрузить информационную базу…** — `*.dt`, запрещён для этого репозитория.

## 6. Выгрузить исходники внешней обработки

Не создавайте заранее каталог с именем обработки. В Конфигураторе откройте внешнюю обработку и используйте доступную в редакторе команду **Выгрузить в файлы…**. В качестве каталога назначения выберите:

```text
$HOME/projects/FoodFactory/src/external-processing
```

В этой версии экспортёр сам создаёт внутри каталог объекта, например `ТестНормализацииАртикула`. Если заранее выбрать каталог `external-processing/ТестНормализацииАртикула`, получится ошибочная двойная вложенность `ТестНормализацииАртикула/ТестНормализацииАртикула`.

Результат в виде XML-файлов и модулей `*.bsl` без файла `*.epf` — корректный текстовый экспорт. Именно эти XML+BSL файлы следует добавлять в Git. В разных вариантах интерфейса команда экспорта может находиться в меню **Файл** активного окна внешней обработки.

Если такой команды в установленной учебной версии нет, не подбирайте параметры CLI наугад. Зафиксируйте ограничение и уточните подтверждённый для 8.3.27.1688 способ текстовой выгрузки. До появления внешней обработки каталог может оставаться пустым.

Как временный fallback можно сохранить бинарный `*.epf` отдельно от исходников:

```bash
cd "$HOME/projects/FoodFactory"
mkdir -p artifacts/external-processing
cp "/полный/путь/к/ИмяОбработки.epf" \
  artifacts/external-processing/ИмяОбработки.epf
git add -f -- artifacts/external-processing/ИмяОбработки.epf
git status --short
```

Перед запуском замените путь после `cp` на реальный путь к обработке. Ключ `-f` нужен намеренно: общий `.gitignore` исключает `*.epf`, а команда разрешает добавить только явно названный артефакт. Не применяйте `git add -f .`.

Бинарный `*.epf` нельзя содержательно сравнить через `git diff`, разрешить конфликт по строкам или нормально проверить на code review. Поэтому `artifacts/` — только временная страховка, а текстовая выгрузка в `src/external-processing/` остаётся приоритетной. После получения текстовых исходников добавьте их обычной командой `git add`, удалите временный бинарный файл через `git rm` и закоммитьте замену.

После выгрузки проверьте результат:

```bash
find "$HOME/projects/FoodFactory/src/external-processing" -type f -print
```

Находясь в `~/projects/FoodFactory`, выполните:

```bash
cat > .gitignore <<'EOF'
# macOS

.LSOverride

# Файловая информационная база и блокировки 1С

*.1cd
*.lck

# Выгрузки, бинарные поставки и обновления 1С
```

Этот файл не исключает `*.xml`, потому что XML — значимая часть файловой выгрузки 1С.

## 8. Инициализировать репозиторий и сделать первый коммит

```bash
cd "$HOME/projects/FoodFactory"
git init
git branch -M main

git config --local user.name "Ваше Имя"
git config --local user.email "you@example.com"
```

Теперь проверьте, что опасные файлы действительно игнорируются:

```bash
touch 1Cv8.1CD local-backup.dt test.epf .env
git check-ignore -v 1Cv8.1CD local-backup.dt test.epf .env
rm 1Cv8.1CD local-backup.dt test.epf .env
```

Затем подготовьте первый коммит:

```bash
git status --short
git add .gitignore AGENTS.md PROGRESS.md docs/28-day-intensive-plan.md src/
git status --short
git diff --cached --stat
git commit -m "chore: initialize FoodFactory learning repository"
```

Перед `git commit` внимательно посмотрите `git status --short`. В индексе не должно быть `1Cv8.1CD`, `*.dt`, `*.cf`, `*.epf`, секретов или временных файлов.

Если `src/external-processing/` пока пуст, `git add` его не добавит — это ожидаемо.

## 9. Вариант с удалённым репозиторием

Сначала создайте **пустой приватный** репозиторий `FoodFactory` в выбранном Git-сервисе. Не добавляйте там README, `.gitignore` или лицензию, чтобы первая отправка не создала конфликт.

SSH-вариант:

```bash
cd "$HOME/projects/FoodFactory"
git remote add origin git@github.com:<ваш-логин>/FoodFactory.git
git remote -v
git push -u origin main
```

HTTPS-вариант:

```bash
cd "$HOME/projects/FoodFactory"
git remote add origin https://github.com/<ваш-логин>/FoodFactory.git
git remote -v
git push -u origin main
```

Замените `<ваш-логин>` и при необходимости домен Git-сервиса. Не вставляйте пароль, токен или приватный SSH-ключ в команды, файлы проекта либо URL remote. Для аутентификации используйте системное хранилище учётных данных или заранее настроенный SSH-ключ.

После отправки:

```bash
git status
git log --oneline --decorate -5
```

## 10. Вариант без remote

Удалённый сервер не обязателен:

```bash
cd "$HOME/projects/FoodFactory"
git remote -v
git status
git log --oneline --decorate -5
```

Пустой вывод `git remote -v` означает, что репозиторий локальный. Коммиты, ветки, история и откат работают как обычно. Но поломка или потеря Mac уничтожит и базу, и локальную Git-историю, поэтому храните отдельную зашифрованную резервную копию на другом носителе. В неё также не следует включать секреты.

## 11. Ежедневный workflow

Каждый учебный день:

1. Выполните упражнение самостоятельно в Конфигураторе.
2. Запустите 1С:Предприятие и проверьте критерии текущего дня.
3. Сохраните конфигурацию и выгрузите её **в файлы** в `src/configuration/`.
4. Если менялась внешняя обработка, повторно выберите `src/external-processing/` как общий каталог назначения; каталог объекта экспортёр создаст сам.
5. Обновите `PROGRESS.md` только фактами, которые действительно подтверждены проверкой. Не отмечайте будущие темы из 28-дневного плана как пройденные.
6. Просмотрите изменения:

   ```bash
   cd "$HOME/projects/FoodFactory"
   git status --short
   git diff --stat
   git diff
   ```

7. Добавьте только проверенные изменения и ещё раз проверьте индекс:

   ```bash
   git add src/ PROGRESS.md AGENTS.md docs/
   git status --short
   git diff --cached --stat
   ```

8. Сделайте небольшой осмысленный коммит:

   ```bash
   git commit -m "feat: add verified FoodFactory learning change"
   ```

   Текст после `feat:` заменяйте точным описанием собственного изменения, например `feat: add nomenclature unit reference`. Не коммитьте незавершённое упражнение под сообщением о готовом результате.

9. Если remote настроен, отправьте коммит:

   ```bash
   git push
   ```

Полезная финальная проверка:

```bash
git status
git log --oneline --decorate -5
```

Рабочее дерево должно быть чистым после коммита. Git фиксирует исходники и учебную документацию, но не доказывает корректность конфигурации: результат каждого упражнения всё равно нужно проверять в Конфигураторе и режиме 1С:Предприятие.
